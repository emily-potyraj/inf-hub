How This Works

What is inf-hub?

inf-hub is an internal tool for tracking inference benchmarking workloads throughout their lifecycle — from initial engineering runs through internal review, accuracy gating, and final publication on NVIDIA's developer pages. It provides a single source of truth for who owns each workload, what its current status is, and what configs have been submitted.

Workload Lifecycle

Each workload moves through these statuses:

  1. not_started — created, not yet being worked on
  2. config_search — engineer is tuning configs
  3. accuracy_gate — blocked on accuracy validation
  4. internal_review — pending sign-off
  5. infmax_submitted — submitted to InfMax
  6. published — live on devzone

Config Versioning

Each workload can have multiple config versions. Upload a new config file or URL from the workload detail page. Versions are numbered sequentially (v1, v2, …). The latest config version is shown as a link in the workload matrix. All config uploads are attributed to the uploader with a timestamp.

Breadth Studies

A breadth study lets you create a large matrix of workloads at once using a crossproduct of dimensions (models × hardware × frameworks × precisions × scenarios × seqlens). All workloads in a study get tagged with a shared study_id and work_type=breadth_test. Duplicate workloads (identical 6-tuple) are silently skipped.

Audit Trail

Every field edit is recorded in an audit log: who changed what, from which value to which value, and when. The audit trail for each workload is accessible from the workload detail page. All edits require authentication via NVIDIA SSO.

JSON Handoff to Joseph

Publication to the public devzone page is a manual process. When workloads reach "published" status, the relevant config JSON is exported and sent to Joseph Chang, who updates the public-facing NVIDIA developer inference benchmarks page. Automated publishing is planned for a future phase.
